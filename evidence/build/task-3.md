## Changes and contracts

- **INT-013:** actual `EvaluationPipeline` calls `portrait_eval.iqa_bridge.evaluate_scene` with declared capture paths. This calls the installed shared `qwen_tmqa.comparison.evaluate_comparison(ComparisonRequest)` in device/audit mode, without a synthetic common source. Each scene stores `iqa_evaluation`. Fewer than two declared images return explicit missing comparison evidence. Core input precision/orientation/source-byte trace is retained.
- **INT-003/004 integration:** Front preserves legacy largest `face_bbox` and exposes every valid `face_bboxes` box, independent per-face region measurements and unverified correspondence. Bridge feeds every box into the shared per-asset ROI assessments with unique unverified person IDs, preventing automatic cross-device identity assignment. Scene audit flags count differences and unverified multi-person correspondence.
- **INT-008:** both real HTTP transports and arbitrary injected adapters undergo strict Pydantic and runtime validation for known requested devices/scenes, ten canonical dimensions plus the explicit old Front `global_exposure`/`highlight_retention` compatibility names, integer 0..100 scores, finite confidence/certainty, hypothesis shape, extra fields, and declared asset/metric evidence references. Reserved transport/claim metadata cannot be supplied by providers. Missing evidence gets no consensus credit.
- **INT-008/012:** transports record the exact actual prompt, prompt SHA-256, ordered device codes, actual decoded JPEG payload hashes, data-URL hashes and canonical actual request hash. Trace is computed before provider transport and survives failure provenance. Prompt context removes path/filename/folder/EXIF/diagnostic metadata recursively, redacts embedded locations, and substitutes declared device identities. No source filename is sent as the anonymous image label.
- **INT-009:** agreement requires identical normalized semantic text and declared evidence; explicit inverse statements are opposition, general differences are unknown. Mixed support/opposition remains opposition. Certainty and overall confidence constrain agreement and final score. Generic visual text no longer receives fabricated objective support. A specific historic measured luminance observation receives objective support only after checking the actual measured fact and declared evidence.
- **INT-009/012:** role or pass changes do not establish a new model identity. Shared configured model names and unknown model identities receive zero independent consensus credit; run binding/findings/report provenance expose this, with an explicit review item. Heuristic/synthetic outputs are provisional C claims. Cross-scene claims use actual measurement availability, audit validity, actual model agreement, and support/counterexample ratio. Three supports with twenty counters are disputed C, not an A tendency. Missing numeric measurements are not fabricated as zero.
- **INT-010:** equal-count order no longer supplies an automatic 0.9 shortcut. Numeric order is strong only against a reference that actually declares 1..N; constant/sparse content cannot prove a content match. Declared ordering with contrary available content requires review. DNG sequence placeholders remain compatible.
- **INT-010:** evaluation consumes an immutable confirmed snapshot of the current project version, verifies source bytes against scanned checksums before analysis and after model passes, detects intervening pairing-version change, and records snapshot ID/version/hash plus image checksums per attempt. Confirmed pairing remains visible independently of analysis/report project status. Confirmation returns the actual persisted snapshot ID.
- **INT-010:** partial failed attempt outputs are removed; `evaluation_failure` retains attempt binding, error type/message and provider input traces. Repeated failed model calls can retry against the same unchanged confirmed snapshot. Worker retries actual transport outages, rate limits and HTTP 5xx, while permanent schema/HTTP failures remain failed rather than being converted to success.
- **INT-011 integration contract:** stable `claim_id` travels through restored observations, findings, direct and nested review payloads, external evidence, bias assessments and attributions; profiles carry `claim_ids`, and aggregated luminance tendencies preserve `source_claim_ids`. Task 4 owns unified final publication projections and path-safe export.
