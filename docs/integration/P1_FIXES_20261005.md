## S-001：盲审静态文件访问边界

原实现先解码请求路径，再交给静态文件处理器继续解码。`/assets/%252e%252e/data/reveal_payload.json` 因此能够在提交评审之前读取揭示数据，且不会记录曝光。

修复将静态文件授权落实到最终解析的文件，并对 GET 和 HEAD 使用相同的访问边界。评审模式只开放评审页和允许的资产，符号链接不能将资产请求指向受保护数据。工程模式的揭示 JSON 仍只能经由揭示 API 返回。

正向流程仍为：打开评审页 → 提交评审并持久化 → 用返回的 `reveal_url` 揭示结果。揭示后，同一评审者对同一场景不能再提交盲审 Gold；重启服务器后仍受曝光记录约束。

`HEAD /api/reveal` 返回 405（`Allow: GET`），不会写入曝光记录。双重编码路径按一次解码后的字面文件名处理；不存在的资产通常返回 404，越过授权边界的目标返回 403。

## S-002：评估结果与运行清单绑定

原清单包含配置、输入数据和提示版本的摘要，但没有评估结果摘要。在同一组图片上，旧配置产生的 PASS 结果可以与新配置产生的清单混用，并进入候选选择和后续人工确认的训练导出。

现在 `evaluate` 根据实际评估对象生成逐场景结果摘要，并写入 `evaluation_run_manifest.json`。CLI 与直接调用候选选择库都会检查绑定；更换结果、修改评估阶段或分数、遗漏场景绑定均不能作为匹配的运行证据。原有图片、配置、提示版本和人工确认检查继续生效。

配置解析和配置摘要使用同一次读取的原始字节，评估和候选选择均消费该次快照。评估期间编辑 YAML，不会把旧策略的结果记为新配置的结果；随后按新配置选择旧结果时会拒绝混用。

摘要用于识别结果与清单是否配套，不是签名，也不认证操作者、模型端点或人工评审者身份。

### 历史结果迁移

历史清单可继续读取；缺少结果绑定时，候选选择会拒绝使用。请重新执行评估，同时保留新生成的结果和清单。不要用新结果或手工补写的摘要去补齐旧清单。

```bash
qwen-tmqa evaluate --root /data/levels --source-root /data/source \
  --config selection.yaml --output results/eval-new
qwen-tmqa select-candidates --results results/eval-new/evaluations.json \
  --root /data/levels --source-root /data/source \
  --config selection.yaml \
  --run-manifest results/eval-new/evaluation_run_manifest.json \
  --splits splits.csv --output results/candidates-new
```

`selection.yaml`、输入图片和本次输出必须配套；候选建议本身不会自动成为训练标签。模型、提示版本和人工确认的配置要求见 [QUICKSTART.md](QUICKSTART.md)。
