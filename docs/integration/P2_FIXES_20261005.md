## 使用与迁移

重新评估并生成 dashboard，新的图片目录不会与旧目录混用。已保存的旧评估结果不会自动更正分数，尤其是旧适配器处理过的百分制低分；请按当前代码重新评估，保留本次配套的结果和运行清单。

```bash
qwen-tmqa evaluate --root /data/levels --source-root /data/source \
  --config selection.yaml --output results/p2-eval
qwen-tmqa visualize --results results/p2-eval/evaluations.json \
  --config selection.yaml --output results/p2-dashboard
```

3.4 的候选 `level_scores`、`selection_confidence` 仍是 0..1，不应用百分制除法。历史 3.2/v3 没有声明分数单位，保留原有兼容处理；需要明确单位时使用 3.3 或 3.4。

评估使用图片摘要检查，检测到持久变化会拒绝结果，前置输入失效会明确报错。它不是文件系统原子快照，无法保证发现完全发生在两次检查之间且随后恢复原字节的改写。评估期间应保持输入数据稳定。

校准默认最少样本数仍来自配置。`sample_count` 记录可比较决策数，`overall_sample_count` 才是权重对应的 overall 有效配对数。`sample_sufficiency.per_model` 列出各模型是否达标；`fusion_weight_scope` 表明研究或生产用途，`production_eligible` 给出最终资格。导入记录中的重复场景、同一场景重复模型或重复评审 ID 会在聚合和写入前拒绝，不能靠复制记录增加样本数。模型来源来自已记录的 `synthetic` 声明，不认证端点或操作者身份。旧校准记录缺少这些字段时按未知来源和研究用途展示。工程页面显示配对数、来源、权重用途与生产资格。

NPY 采用 512 MiB 原文件读取上限和 512 MiB 预计解码分配预算，并应用现有 Pillow 的像素拒绝阈值。单个文件过大、头部异常、数据截断、多余尾部数据、对象数组或不支持的图像布局都会作为无效资产返回，健康候选继续评估。预算包含规范化和哈希临时数组，并非只限制 NPY 文件大小。

审计检查的是保存的内部 0..1 分数，不通过历史百分制反序列化去纠正无效值。旧行为证据没有原始 `output` 时需重新运行证据生成流程；不能仅补写一个看似合法的摘要。正常证据生成脚本已经保存输出和对应 SHA-256。

## 复测

在 Python 3.10 和 3.12 独立环境中分别安装并运行。激活环境使测试中的 `python` 子进程使用同一版本。

```bash
python -m venv .venv-iqa
source .venv-iqa/bin/activate
python -m pip install -e './packages/iqa[dev]'
cd packages/iqa

# 八项 P2 的新增回归
python -m pytest -q tests/test_standalone_p2_*.py

# 完整验证
python -m pytest -q
python -m ruff check .
python -m compileall -q src tests scripts
python -m build
python scripts/verify_wheel_install.py --dist dist \
  --target /tmp/iqa-p2-wheel-target --expected-version 0.2.0
python scripts/verify_cli_contract.py --config configs/default.yaml \
  --workdir /tmp/iqa-p2-cli
bash scripts/run_verified_experiment.sh /tmp/iqa-p2-experiment
```

使用新的临时输出路径。模型调用使用 MockTransport，NPY 巨大分配用安全哨兵拦截，不申请巨大数组；训练导出使用测试用人工确认。这些测试检验软件合同和流程，不证明真实模型准确率或训练收益。
